## Patterns
**Verified**
- Central seam: `Run Orchestrator` is the single high-level module/test seam; it accepts `RunRequest` and returns `RunResult` (`SPEC.md:64-70,130-137`).
- Adapters are separated for Bug Source, Repository Provider, Execution Environment, Investigator, Verifier, Store, Sanitizer, Result Sink, clock, identifiers (`SPEC.md:66-69`).
- GitHub-first concrete adapters: GitHub Issue Bug Source, GitHub Repository Provider, GitHub Issue Result Sink (`SPEC.md:69-77`).
- Snapshot immutability: issue title/body/comments/etc. are snapshotted once; target ref resolves once to an exact SHA; later remote edits do not mutate the run (`SPEC.md:73-77`; `PRD.md:194-199`).
- Result sink writes only a sanitized terminal projection and uses a stable marker so each run has exactly one comment; it never changes issue lifecycle state (`SPEC.md:76-77`).
- Execution model is isolated/non-privileged: fresh workspace per actor, read-only inputs, finite quotas, no host mounts/socket/device/root access (`SPEC.md:81-85`).
- Lifecycle requires primary investigation, verification, and sometimes a second independent investigation before `NOT_REPRODUCED`; candidates cannot self-certify (`SPEC.md:87-94`; `PRD.md:258-279`).
- Run Record is versioned JSON from an append-only event journal; sanitization happens before persistence/publication (`SPEC.md:110-117`).
- Benchmark cases separate visible input from a hidden evaluation oracle (`SPEC.md:121-126`; `PRD.md:533-565`).
- Evaluation reports measure outcome classes, false positives, escalation, second-investigator behavior, resource use, and failure modes separately (`SPEC.md:119-126`; `PRD.md:580-647`).

## Gotchas / lessons learned
**Verified**
- `REPRODUCED` requires untouched production/application code at the resolved revision plus independent verification; a generic failing test is insufficient (`PRD.md:254-267,361-372`).
- `NOT_REPRODUCED` is only a bounded investigation result; it is not proof the bug does not exist (`PRD.md:374-382`).
- `INCONCLUSIVE` must name a material blocker and attempted alternatives; it is not an escape hatch (`PRD.md:384-395`).
- Unsupported execution capabilities must be classified separately and not counted as failures (`SPEC.md:81-85`; `PRD.md:355-360`).
- No hidden persistent agent memory: each run must start fresh; prior evidence stays explicit, not authoritative (`PRD.md:431-438,681-684`).
- Secrets/sensitive data must be sanitized before storage or publication (`SPEC.md:115-117`; `PRD.md:462-466,693-696`).
- Automatic issue lifecycle management, automatic PR creation, and repair scope are out of MVP scope (`PRD.md:84-105,329-345,512-530,673-700`).
- GitHub issue/PR number space is shared; bare `#42` may refer to either and must be resolved explicitly (`docs/agents/issue-tracker.md:26`).
- No ADRs are present under `docs/adr/`, and no `CONTEXT-MAP.md` exists; only the root `CONTEXT.md` is currently defined.
